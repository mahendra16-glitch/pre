# iOS / iPadOS printer connectivity: Wi-Fi, LAN, Bluetooth

## What changed (transport only)
Bills and KOTs are still generated by the existing `PrintByteConvert` and generator code, from the same API data. No API, field mapping, calculation, template or UI was changed. The only change is how the generated ESC/POS bytes reach the printer on iPhone and iPad.

Before this change, every iOS print function sent bytes over Bluetooth only. Printers configured as `wifi` failed on iOS with "kot failed" or "Failed to bluetooth connect".

## Routing on iOS
`IosPrintTransport` picks the route for each print job from the **existing** profile fields:

| Profile (existing fields) | Route on iPhone/iPad |
|---|---|
| `printer_name = wifi`, valid `wifi_printer_ip`, `mac_printer_ip` empty | **Wi-Fi/LAN (TCP)** |
| Any printer with `mac_printer_ip` set | **Bluetooth, exactly as before** |
| Anything else | Unchanged behaviour |

Android and Windows code paths are not touched: every edit is inside iOS-only functions. `NetworkPrinterResolver` returns null on non-iOS platforms.

## New files
- `lib/helper/wifi_printer/network_printer_address.dart`: printer address parsing and validation (`ip`, `ip:port`, `[ipv6]:port`, hostname; default port 9100).
- `lib/helper/wifi_printer/network_printer_target.dart`: `NetworkPrinterResolver`, which reads the existing profile fields.
- `lib/helper/wifi_printer/wifi_printer_service.dart`: TCP printing shared by Wi-Fi and Ethernet printers. It has a lock per printer (no interleaved or duplicate jobs) and a 5 s connect timeout. Only the connect step is retried. Data is sent in 4 KB chunks, each flushed. It never resends after any byte has gone out (`mayHavePrinted`). Idle sockets close when the app goes to background or the network changes, and a session auto-closes after 60 s idle. Diagnostics go to the existing Print Debug log.
- `lib/helper/wifi_printer/ios_print_transport.dart`: drop-in for the `PrintBluetoothThermal` connect / writeBytes / disconnect / connectionStatus calls.
- `packages/ios_ble_printer/`: new native CoreBluetooth module (Swift, iOS only, local plugin). It scans, connects by the same identifier stored in `mac_printer_ip`, and finds the writable characteristic. It sizes packets with `maximumWriteValueLength` (MTU), uses write-with-response when available, otherwise write-without-response with `canSendWriteWithoutResponse` flow control. It runs several printers at once, reports Bluetooth off / unauthorized / out of range, and returns `bytesSent` on failure. **Off by default** (`IosPrintTransport.useNativeBle = false`). The existing Bluetooth path stays active until this is tested on real devices.
- `test/wifi_printer_test.dart`: 11 tests (address parsing, plus real TCP against a local fake printer: exact bytes, 50 KB payload, copies, no interleaving, offline printer, lock release).

## Modified files
- `pubspec.yaml`: added the `ios_ble_printer` path dependency (no third-party package). `pubspec.lock` gained only that entry.
- `ios/Runner/Info.plist`: added `NSLocalNetworkUsageDescription`. Bluetooth keys already existed. No `NSBonjourServices` (no Bonjour discovery). No new background modes.
- 26 iOS print functions: `PrintBluetoothThermal.*` changed to `IosPrintTransport.*`. Empty-MAC "fail" checks now let configured Wi-Fi printers through. The Bluetooth printer scan before a bill print (`pairedBluetooths`) is skipped for Wi-Fi bill printers.

## Setting up a printer
**Wi-Fi or LAN printer**
1. Give the printer a fixed IP: either a static IP on the printer, or a DHCP reservation on the router. A plain DHCP address can change, and printing then stops.
2. In the existing printer settings (admin panel), set the printer type to `wifi`. Enter the IP in the Wi-Fi printer IP field. For a port other than 9100, enter `192.168.1.50:9101`. Leave the Bluetooth MAC empty for that printer.
3. The iPhone or iPad must be on the same network. On the first print, iOS asks for Local Network access: tap **Allow**. If it was denied, turn it on under Settings → Privacy & Security → Local Network → MyGenie.

**Bluetooth (BLE) printer**: unchanged. Use the existing Get Printer screen.

## Known limitations
- Bluetooth Classic (MFi / ExternalAccessory) is **not implemented**. Generic Classic/SPP printers cannot work on iOS at all. MFi printers need the maker's SDK, a protocol string, and Apple MFi approval.
- iOS gives no API to check Local Network permission. A denied permission and an unreachable printer look the same, so the error message covers both.
- Background printing is limited by iOS. A job that is already sending finishes while iOS allows it; nothing new is printed in background.
- Print quality (alignment, raster logo, code pages) comes from the existing ESC/POS generator and is the same for every connection type.
